# P3.5 — Recap integration validation

Extends the existing real HTTP workflow to verify the daily list and detail after pending/approved/cancelled absence, successful QR check-in, selfie rejection and re-approval, checkout, ordered attendance cancellation, retake authorization and successful retake. Each assertion reads the real server; list and detail must match. Employee and anonymous recap access is denied. Temporary accounts, DB, PDF and JPEG only; no real employee data.

Four additional tests use disposable WAL databases and two independent SQLite connections. A read snapshot is established by authentication before the second connection commits approval or cancellation; list/detail must remain internally consistent and the next read must see the new state. An uncommitted record must remain invisible and rollback leaves the same recap. A 3001-row synthetic dataset (3000 attendance records with distinct timestamps) verifies pagination, detail equality, no writes and database integrity while logging elapsed handler times. These are measured diagnostics, not a fixed latency SLA; they exclude HTTP/network and depend on hardware and load. Detail still builds the daily dataset before selecting one member.

Run npm run test:security (expected 123 tests), npm run build, npx tsc --noEmit --noUncheckedSideEffectImports, and npm run check:local with the isolated test-data directory. P3 completion requires local and CI pass. Browser UI, Excel, manual camera tests, performance profiling under representative production load and release hardening remain later phases. No new migrations or production deployment.
