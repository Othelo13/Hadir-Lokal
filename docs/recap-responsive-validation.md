# P4.6 — Responsive UI and accessibility regression

This change completes the code and automated regression portion of P4.6. The daily recap table becomes member cards on viewports at or below 760px while retaining the table headers in a visually clipped form and providing visible cell labels. The page controls, buttons and date/search inputs wrap and have usable touch targets; the admin detail modal has viewport-relative height and a one-column stats/actions layout at <=420px. Rules are scoped under daily-recap selectors so the existing event history, QR and Excel UI remain unaffected. No storage/schema or backend API changes.

The detail dialog now traps keyboard Tab/Shift+Tab within visible enabled controls, handles Escape without losing a pending write, and restores keyboard focus to the originating member button after closing. Confirmation prompts focus the reason field or confirm control. Background scroll stays locked during detail inspection, and an empty focusable list falls back to the dialog surface. Modal close/backdrop click are disabled during a write; confirmation content is not discarded through backdrop click. Private photo/attachment access remains server-authorized.

Regression coverage: keyboard focus wrapping, zero/one controls, mobile visible labels, scoped CSS, modal source accessibility hooks, server pagination, and authorization-related UI guards. The automated suite tests these invariants, but DOES NOT constitute a real-browser visual, screen reader, or touch test. For sign-off, manually inspect at 1440px, 768px, 390px and 320px with isolated development data, keyboard-only navigation and network throttling. Check scrolling, modal close/focus, preview and attachment download under active admin session, rejected/admin denied requests, all statuses, no sensitive reasons in list, and successful mutation refreshes both views. Do not perform destructive cancellation on real/production data. P4 can be closed only after local 172-test verification, CI, and manual browser sign-off.

No new dependencies, migration or deployment. main and the production site remain untouched.
