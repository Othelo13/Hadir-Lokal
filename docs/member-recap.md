# Evaluasi P4 — Rekap absensi per anggota

Requested behavior: The 'Rekap absensi' navigation now shows a member-centric MONTHLY recap, not daily check-in/check-out rows. The table includes every currently active employee account (including zero evidence), never an admin role account. Columns: member, hadir, tidak hadir, izin, sakit, perlu tinjauan and link to the existing Riwayat & ekspor. Late check-in counts as hadir, with a separate late annotation. The original daily-recap API/detail and admin actions are retained for internal use; no existing endpoint contract was broken.

GET /api/app?action=member-recap&month=YYYY-MM&q=&page=1&pageSize=10 is read-only and admin-only in one SQLite snapshot. Counts are derived from historicalDailyRecap day by day, using history-based eligibility and effective approved leave/sick. Missing days are counted as 'tidak hadir' ONLY when the day is completed, fully covered, working, member eligible and there is neither valid attendance nor approved absence nor conflicting/provisional evidence. Today's missing attendance, nonworking days, future dates, dates before historical coverage, pre-membership and nonemployee-role history do not generate absence. Pending/selfie-review conflicts are separate 'perlu tinjauan' and not silently classified as absent. Dates with incomplete historical coverage produce a warning. Note that historic missing days BEFORE the history migration cannot be inferred; zero is not a verified perfect attendance record.

Member filtering and pagination are performed on the server, not on visible rows. The input month defaults to office's current month. The legacy Riwayat & ekspor and all P4 daily detail functionality remains unchanged, although new monthly screen links to legacy history view rather than claiming to provide a per-date detail. Browser testing and performance benchmarking of an entire month still required. This is a semantic change needing domain review before release; no production deployment, new tables, or migrations.
