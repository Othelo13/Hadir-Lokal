# P4.3 — Date filter, search and pagination

The admin daily recap now has a native date input, a name/email search input, reset, refresh and server pagination 10/20/50. No additional frontend data source or route was introduced. All filters are sent to GET /api/app?action=daily-recap: date is YYYY-MM-DD; q is a trimmed literal; page and pageSize select a server-scoped slice. The server searches the complete selected day's rows and returns total/totalPages.

The empty selectedDate state omits date; the server chooses today's calendar date in the office timezone. The UI displays the last server-returned date until a new response arrives. Reset clears the date/search, resets to page 1 and fetches again; when the day changes, the server determines the new current date. Search is debounced by 300ms. While typing, the previous request is aborted and previous results are hidden; old results cannot be shown for an uncommitted search. The effect's active/AbortController guards also ignore stale responses after changing date, page, size or unmount. Page is reset to 1 on filter and size changes; server-clamped page is reflected back to state.

Generic status labels and notes remain safe; private medical details stay in admin-only detail and aren't placed in the table. The legacy history/export feature is unchanged. P4.4 adds detail interactions and P4.5 adds review/cancellation. Seven pure/client tests cover query shape, UTF-8 encoding, server office date, page sizes and reset behavior. End-to-end browser validation remains P4.6. No new migrations or dependencies; production/main untouched.
